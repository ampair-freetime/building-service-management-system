# คู่มือติดตั้งระบบ CS Building Care

ระบบเว็บสำหรับแจ้งซ่อม แจ้งทำความสะอาด และแจ้งของหาย/ของที่พบภายในอาคาร

- **ผู้ใช้ทั่วไป:** สแกน QR Code ที่ติดอยู่ในห้องเพื่อแจ้งเรื่องพร้อมแนบรูปได้ทันที ไม่ต้องสมัครสมาชิก
- **เจ้าหน้าที่ (แม่บ้าน ช่าง ธุรการ):** รับงานและอัปเดตสถานะปิดงานผ่านหน้าเว็บ
- **ผู้ดูแลระบบ (Admin):** จัดการบัญชีเจ้าหน้าที่ เพิ่มข้อมูลห้อง และสร้าง QR Code

คู่มือนี้ออกแบบมาให้ติดตั้งตามได้ทีละขั้นตอนโดยไม่ต้องเขียนโค้ด ทุกอย่างรันผ่านสคริปต์คำสั่งเดียวคือ `./deploy/bcare.sh`

## ส่วนที่ 1: สิ่งที่ต้องเตรียมก่อนเริ่ม

สิ่งที่ต้องมีก่อนติดตั้ง:

- เซิร์ฟเวอร์ Linux 64-bit (แนะนำ Ubuntu 22.04 หรือ 24.04) สเปกอย่างน้อย 2 CPU, RAM 4 GB, พื้นที่ว่าง 20 GB พร้อมสิทธิ์ `sudo`
- ชื่อโดเมน เช่น `care.cs.science.cmu.ac.th` (**สำคัญ:** โดเมนนี้จะถูกนำไปสร้างเป็นลิงก์ใน QR Code หากพิมพ์ QR Code ไปติดแล้วจะเปลี่ยนชื่อโดเมนทีหลังไม่ได้)
- พื้นที่เก็บรูปภาพบน Cloudflare R2 (ดูวิธีสร้างในข้อ 1.1)
- บัญชีอีเมลสำหรับให้ระบบส่งเมลแจ้งเตือนอัตโนมัติ (ดูวิธีเตรียมในข้อ 1.2)
- ชื่อและอีเมลสำหรับใช้สร้างบัญชีผู้ดูแลระบบ (Admin) คนแรก

> **ข้อควรระวัง:** ข้อมูลรหัสผ่านและ Key ที่ได้จากข้อ 1.1 และ 1.2 เป็นความลับ หากจดพักไว้ในไฟล์ข้อความ (เช่น Notepad) แนะนำให้ลบทิ้งทันทีหลังติดตั้งเสร็จ

### 1.1 สร้างพื้นที่เก็บรูปภาพด้วย Cloudflare R2 (ใช้ฟรี 10 GB)

ในขั้นตอนนี้ เราต้องการข้อมูล 4 ค่าไปกรอกในระบบ ได้แก่ **Account ID**, **Bucket Name**, **Access Key ID** และ **Secret Access Key**

1. **สมัครและเข้าสู่ระบบ Cloudflare:** ไปที่ https://dash.cloudflare.com/sign-up (หากมีบัญชีอยู่แล้วให้เข้าที่ https://dash.cloudflare.com)
2. **เปิดใช้งาน R2:** ที่เมนูด้านซ้าย เลือก **R2 Object Storage** (หรือเข้าผ่าน https://dash.cloudflare.com/?to=/:account/r2/overview)
   - การใช้งานครั้งแรก ระบบจะให้กด **Purchase R2 Plan / Add R2** และผูกบัตรเครดิตหรือ PayPal เพื่อยืนยันตัวตน (ใช้งานไม่เกิน 10 GB ไม่มีค่าใช้จ่าย)
3. **คัดลอก Account ID:** ดูที่แถบด้านขวาของหน้า R2 Overview ในกรอบ **Account Details** กดไอคอนคัดลอกตรง **Account ID** (รหัสยาว 32 ตัวอักษร)
4. **สร้าง Bucket สำหรับเก็บรูป:** กดปุ่ม **Create bucket**
   - **Bucket name:** ตั้งชื่อด้วยตัวพิมพ์เล็ก เช่น `cs-building-care` (ใช้เป็นค่า **Bucket Name**)
   - **Location:** เลือกเป็น Automatic แล้วกด **Create bucket**
   - *หมายเหตุ:* **ไม่ต้อง**เปิด Public access หรือ r2.dev subdomain เพราะตัวระบบจะจัดการสิทธิ์การเปิดดูรูปให้เองอย่างปลอดภัย
5. **สร้าง API Token ให้ระบบเชื่อมต่อ:** กลับไปที่หน้า R2 Overview มองทางขวามือในกรอบ Account Details กด **Manage API tokens** แล้วเลือก **Create Account API token**
   - **Token name:** `cs-building-care`
   - **Permissions:** เลือก **Object Read & Write**
   - **Specify bucket(s):** เลือก **Apply to specific buckets only** แล้วเลือกชื่อ bucket ที่สร้างไว้ในข้อ 4
   - **TTL:** เลือก Forever จากนั้นกด **Create Account API Token**
6. **บันทึกค่า Key เก็บไว้ทันที** (หน้านี้จะแสดงแค่ครั้งเดียว หากปิดไปแล้วจะกลับมาดูซ้ำไม่ได้):
   - คัดลอกค่า **Access Key ID** และ **Secret Access Key** ที่อยู่ในหัวข้อ *"Use the following credentials for S3 clients"*
   - *ข้อควรระวัง:* ไม่ต้องใช้ค่าในช่อง Token value และไม่ต้องกังวลเรื่องค่า Endpoint เพราะระบบจะสร้างจาก Account ID ให้อัตโนมัติ

### 1.2 เตรียมบัญชีอีเมลสำหรับส่งเมลแจ้งเตือน (Gmail)

ในขั้นตอนนี้ เราต้องการ **อีเมล Gmail** และ **App Password 16 หลัก**

1. **เตรียมบัญชี Gmail:** แนะนำให้สมัครบัญชีใหม่แยกเฉพาะสำหรับระบบ เช่น `cs.buildingcare@gmail.com` ที่ https://accounts.google.com/signup
2. **เปิดการยืนยันตัวตน 2 ขั้นตอน (2-Step Verification):** ไปที่ https://myaccount.google.com/signinoptions/twosv กด **Turn on** แล้วทำตามขั้นตอนเพื่อผูกเบอร์โทรศัพท์
   *(จำเป็นต้องเปิดส่วนนี้ก่อน ไม่เช่นนั้นจะไม่เห็นเมนูสร้าง App passwords)*
3. **สร้าง App Password:** ไปที่ https://myaccount.google.com/apppasswords
   - **App name:** พิมพ์ชื่อ `CS Building Care` แล้วกด **Create**
   - ระบบจะแสดงรหัสผ่าน **16 ตัวอักษร** (เช่น `abcd efgh ijkl mnop`) ให้คัดลอกเก็บไว้ เวลาเอาไปกรอกในระบบให้พิมพ์ติดกันทั้งหมดโดย**ไม่ต้องเว้นวรรค**
   - *ข้อควรระวัง:* ห้ามใช้รหัสผ่านเข้า Gmail ตามปกติ เพราะระบบจะไม่สามารถล็อกอินเพื่อส่งเมลได้

สรุปค่าที่จะต้องนำไปกรอกในขั้นตอนที่ 4:

| ตัวแปร | ค่าที่ต้องใส่ |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORT` | `587` (มีตั้งค่าเริ่มต้นไว้ให้แล้ว ไม่ต้องแก้) |
| `SMTP_USERNAME` | อีเมล Gmail เต็ม เช่น `cs.buildingcare@gmail.com` |
| `SMTP_PASSWORD` | รหัส App Password 16 ตัวอักษร (พิมพ์ติดกันไม่มีช่องว่าง) |
| `MAIL_FROM` | `"CS Building Care <cs.buildingcare@gmail.com>"` (ใช้อีเมลเดียวกับ `SMTP_USERNAME`) |

- บัญชี Gmail ปกติส่งเมลได้ประมาณ **500 ฉบับต่อวัน** ซึ่งเพียงพอต่อการใช้งานของระบบนี้
- หากใช้อีเมลของมหาวิทยาลัย (`@cmu.ac.th`) ทางผู้ดูแลระบบกลางอาจปิดฟีเจอร์ App passwords ไว้ การใช้ Gmail แยกจะตั้งค่าง่ายกว่า
- หากใช้ผู้ให้บริการอีเมลเจ้าอื่น ต้องรองรับการเชื่อมต่อแบบ **STARTTLS ที่พอร์ต 587** (ดูคู่มือของ Google เพิ่มเติมเรื่อง [App passwords](https://support.google.com/accounts/answer/185833))

## ส่วนที่ 2: ขั้นตอนการติดตั้ง

ให้เปิด Terminal เชื่อมต่อไปยังเครื่องเซิร์ฟเวอร์ แล้วรันคำสั่งตามลำดับด้านล่าง

### ขั้นตอนที่ 1: ติดตั้งโปรแกรมพื้นฐาน (ทำครั้งเดียว หากมี Git และ Docker แล้วข้ามได้)

```bash
sudo apt update && sudo apt install -y git
curl -fsSL https://get.docker.com | sudo sh && sudo usermod -aG docker $USER
```

เมื่อรันเสร็จแล้ว **ให้ออกจากเซิร์ฟเวอร์ (`exit`) แล้วล็อกอินเข้ามาใหม่อีกครั้ง** เพื่อให้สิทธิ์การรันคำสั่ง `docker` มีผล

### ขั้นตอนที่ 2: ดาวน์โหลดโค้ดระบบลงเซิร์ฟเวอร์

```bash
sudo mkdir -p /srv/building-care && sudo chown $USER /srv/building-care
git clone https://github.com/ampair-freetime/building-service-management-system.git /srv/building-care
cd /srv/building-care
```

> **หมายเหตุ:** ทุกครั้งที่ล็อกอินเข้าเซิร์ฟเวอร์มาใหม่ อย่าลืมพิมพ์ `cd /srv/building-care` เพื่อเข้าโฟลเดอร์ระบบก่อนรันคำสั่งอื่น

### ขั้นตอนที่ 3: สร้างไฟล์ตั้งค่าระบบ

```bash
./deploy/bcare.sh install
```

ในการรันครั้งแรก ระบบจะสร้างไฟล์ `.env` ขึ้นมาแล้ว**หยุดการทำงานชั่วคราว** พร้อมแจ้งรายการค่าที่คุณต้องกรอกเพิ่มเติม ให้ทำขั้นตอนที่ 4 ต่อได้เลย

### ขั้นตอนที่ 4: กรอกข้อมูลการตั้งค่าในไฟล์ `.env`

เปิดไฟล์ตั้งค่าด้วยคำสั่ง:

```bash
nano .env
```

- ใช้ปุ่มลูกศรเลื่อนหาบรรทัดที่ต้องแก้ หรือกด **Ctrl+W** แล้วพิมพ์ `REPLACE_` เพื่อค้นหา
- ให้**ลบข้อความตัวอย่างหลังเครื่องหมาย `=` ออกทั้งหมด** แล้วใส่ค่าจริงลงไปแทน (ระวังอย่าลบแค่คำว่า `REPLACE_`)
- ค่า Secret และรหัสผ่านฐานข้อมูลอื่นๆ สคริปต์ได้สุ่มและกรอกไว้ให้เรียบร้อยแล้ว ไม่ต้องแก้ไข

| ค่าเดิมในไฟล์ | ตัวอย่างการแก้ไข |
| --- | --- |
| `PUBLIC_BASE_URL=https://REPLACE_DOMAIN.example.org` | `PUBLIC_BASE_URL=https://care.cs.science.cmu.ac.th` |
| `BACKEND_CORS_ORIGINS=["https://REPLACE_DOMAIN.example.org"]` | `BACKEND_CORS_ORIGINS=["https://care.cs.science.cmu.ac.th"]` |
| `R2_ACCOUNT_ID=REPLACE_R2_ACCOUNT_ID` | `R2_ACCOUNT_ID=<ใส่ Account ID จาก Cloudflare>` |
| `R2_ACCESS_KEY_ID=REPLACE_...` / `R2_SECRET_ACCESS_KEY=REPLACE_...` / `R2_BUCKET_NAME=REPLACE_...` | ใส่ค่าจาก Cloudflare R2 ให้ตรงตามชื่อตัวแปร |
| `SMTP_HOST=REPLACE_SMTP_HOST` | `SMTP_HOST=smtp.gmail.com` |
| `SMTP_USERNAME=REPLACE_SMTP_USERNAME` | `SMTP_USERNAME=cs.buildingcare@gmail.com` |
| `SMTP_PASSWORD=REPLACE_SMTP_PASSWORD` | `SMTP_PASSWORD=<ใส่ App Password 16 ตัว>` |
| `MAIL_FROM="CS Building Care <REPLACE_SENDER@example.org>"` | `MAIL_FROM="CS Building Care <cs.buildingcare@gmail.com>"` |

**เฉพาะกรณีที่เซิร์ฟเวอร์อยู่หลัง Reverse Proxy ของหน่วยงาน (ตรงกับรูปแบบที่ 2 ในขั้นตอนที่ 6):** ให้แก้เพิ่มอีก 2 บรรทัดนี้ด้วย

| ค่าเดิมในไฟล์ | ตัวอย่างการแก้ไข | เหตุผล |
| --- | --- | --- |
| `FRONTEND_BIND_ADDRESS=127.0.0.1` | `FRONTEND_BIND_ADDRESS=10.10.5.20` (ใส่ IP ภายในของเครื่องเซิร์ฟเวอร์นี้) | เปิดให้เครื่อง Reverse Proxy เชื่อมต่อเข้ามาที่เครื่องนี้ได้ |
| `EDGE_PROXY_CIDR=` | `EDGE_PROXY_CIDR=10.10.1.5/32` (ใส่ IP ของเครื่อง Proxy ตามด้วย `/32`) | จำกัดให้รับการเชื่อมต่อเฉพาะจาก Proxy เท่านั้น (เครื่องอื่นจะได้ 403) และช่วยให้ระบบอ่าน IP จริงของผู้ใช้ได้ถูกต้อง |

เมื่อกรอกครบแล้ว ให้บันทึกและออกจากโปรแกรมโดยกด **Ctrl+O** -> กด **Enter** -> กด **Ctrl+X**

### ขั้นตอนที่ 5: เริ่มติดตั้งและเปิดระบบ

รันคำสั่งติดตั้งอีกครั้ง:

```bash
./deploy/bcare.sh install
```

- การติดตั้งครั้งแรกจะใช้เวลาประมาณ **5-10 นาที** ในการดาวน์โหลดและประกอบระบบ ให้รอจนข้อความวิ่งเสร็จ
- ในช่วงท้าย ระบบจะให้ตั้งค่า **อีเมล ชื่อ และรหัสผ่าน** สำหรับบัญชีผู้ดูแลระบบ (Admin) คนแรก:
  - รหัสผ่านต้องยาวอย่างน้อย 8 ตัวอักษร และประกอบด้วย **ตัวพิมพ์ใหญ่ ตัวพิมพ์เล็ก ตัวเลข และอักขระพิเศษ** อย่างน้อยอย่างละ 1 ตัว (เช่น `Care@2026`)
  - ขณะพิมพ์รหัสผ่าน **หน้าจอจะไม่แสดงตัวอักษรใดๆ** เพื่อความปลอดภัย ให้พิมพ์จนครบแล้วกด Enter จากนั้นพิมพ์ยืนยันซ้ำอีกครั้ง
- สคริปต์จะตั้งเวลาสำรองข้อมูลฐานข้อมูลอัตโนมัติให้ทุกวัน เวลา 02:00 น.

หากติดตั้งสมบูรณ์ ช่วงท้ายสุดจะแสดงข้อความ 3 บรรทัดนี้:

```text
SMTP: CONNECTIVITY_OK (no email sent)
R2: BUCKET_ACCESS_OK (upload/delete not tested)
{"status":"ok"}
```

หากมีบรรทัดใดขึ้นว่า `FAILED` ให้ตรวจสอบวิธีแก้ไขใน [ส่วนที่ 4](#ส่วนที่-4-การแก้ปัญหาเบื้องต้น) แล้วกลับไปแก้ไฟล์ `.env` จากนั้นรันคำสั่งในขั้นตอนที่ 5 ซ้ำได้เลย (ขั้นตอนไหนที่ทำสำเร็จไปแล้ว ระบบจะข้ามให้เอง)

### ขั้นตอนที่ 6: ตั้งค่า HTTPS (เลือกรูปแบบใดรูปแบบหนึ่ง)

**รูปแบบที่ 1: เซิร์ฟเวอร์ออกอินเทอร์เน็ตโดยตรง (ไม่มี Reverse Proxy คั่น)**
เซิร์ฟเวอร์เครื่องนี้จะจัดการใบรับรอง HTTPS เอง (ต้องแจ้งฝ่ายไอทีให้ชี้โดเมนมาที่ IP ของเครื่องนี้ และเปิดพอร์ต 80 กับ 443 ให้เข้าถึงจากอินเทอร์เน็ตได้ก่อน)

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
./deploy/bcare.sh https care.cs.science.cmu.ac.th
```

กรอกอีเมลและกดยอมรับเงื่อนไขบนหน้าจอตามที่ Certbot ถามจนเสร็จ

**รูปแบบที่ 2: มีเครื่อง Reverse Proxy ของหน่วยงานดูแลเรื่อง HTTPS อยู่แล้ว**
ไม่ต้องรันคำสั่งใดๆ เพิ่มบนเครื่องนี้ แต่ให้แจ้งผู้ดูแลระบบ Proxy ตั้งค่าตามรายละเอียดดังนี้:

> ขอตั้งค่า Reverse Proxy สำหรับโดเมน `care.cs.science.cmu.ac.th` ให้ส่งทราฟฟิกต่อไปที่ `http://<IP ภายในของเครื่องนี้>:8080` โดยมีรายละเอียดดังนี้ครับ:
> - ส่งต่อ Header `X-Forwarded-Proto: https` และ `X-Forwarded-For` (IP จริงของผู้ใช้)
> - ตั้งค่าขนาดไฟล์อัปโหลดสูงสุดที่ 60 MB (`client_max_body_size 60m`) และตั้ง Timeout ไว้ที่ 120 วินาที
> - ปิดการทำ Cache สำหรับ Path ที่ขึ้นต้นด้วย `/api/`

*(ทั้งนี้ ไม่จำเป็นต้องตั้ง Firewall กั้นพอร์ต 8080 เพิ่มเติม เพราะตัวระบบจะบล็อกการเชื่อมต่อที่ไม่ได้มาจาก IP ในค่า `EDGE_PROXY_CIDR` ให้อัตโนมัติ)*

### ขั้นตอนที่ 7: ทดสอบการใช้งานจริง

1. เปิดเบราว์เซอร์ไปที่ `https://<ชื่อโดเมน>/health` จะต้องแสดงข้อความ `{"status":"ok"}`
2. เปิดหน้า `https://<ชื่อโดเมน>/staff-login` แล้วลองล็อกอินด้วยบัญชี Admin ที่สร้างไว้ในขั้นตอนที่ 5
3. ทดลองสร้างห้อง -> กด Generate QR -> ลองใช้โทรศัพท์มือถือ **(ปิด Wi-Fi แล้วใช้เน็ตมือถือ 4G/5G)** สแกน QR Code เพื่อทดสอบแจ้งเรื่องพร้อมแนบรูปถ่าย
4. ทดลองเพิ่มบัญชีเจ้าหน้าที่ 1 คน แล้วตรวจสอบว่ามีอีเมลคำเชิญส่งไปถึงหรือไม่ (อย่าลืมตรวจในโฟลเดอร์ Spam/จดหมายขยะ)

หากทดสอบผ่านครบทั้ง 4 ข้อ ก็พร้อมใช้งานจริงได้ทันทีครับ

## ส่วนที่ 3: การดูแลระบบประจำวัน

ทุกครั้งที่ใช้คำสั่งจัดการระบบ ให้เข้าไปที่โฟลเดอร์โปรเจกต์ด้วยคำสั่ง `cd /srv/building-care` ก่อนเสมอ

| งานที่ต้องการทำ | คำสั่ง |
| --- | --- |
| ตรวจสอบสถานะการทำงานของระบบ | `./deploy/bcare.sh status` |
| ดู Log ข้อผิดพลาดล่าสุดของระบบหลังบ้าน (กด **Ctrl+C** เพื่อออก) | `./deploy/bcare.sh logs backend` |
| สั่งสำรองข้อมูลทันที (นอกเหนือจากรอบอัตโนมัติตอน 02:00 น.) | `./deploy/bcare.sh backup` |
| กู้คืนข้อมูลจากไฟล์สำรอง | `./deploy/bcare.sh restore /srv/backups/<ชื่อไฟล์>.dump` |
| อัปเดตระบบเป็นเวอร์ชันล่าสุด (มีการสำรองข้อมูลให้อัตโนมัติก่อนอัปเดต) | `./deploy/bcare.sh update` |
| โหลดค่าใหม่หลังจากแก้ไขไฟล์ `.env` | `./deploy/bcare.sh install` |

- ไฟล์สำรองฐานข้อมูลจะถูกเก็บไว้ที่ `/srv/backups` โดยเก็บย้อนหลัง 14 วัน **แนะนำให้คัดลอกไฟล์สำรองออกไปเก็บไว้นอกเครื่องเซิร์ฟเวอร์เป็นประจำ** (ส่วนไฟล์รูปภาพจะถูกเก็บแยกไว้บน Cloudflare R2 ไม่ได้รวมอยู่ในไฟล์ `.dump` นี้)
- **คำเตือน:** ห้ามรันคำสั่ง `docker compose down -v` เด็ดขาด เพราะพารามิเตอร์ `-v` จะสั่งลบข้อมูลในฐานข้อมูลทั้งหมดทิ้ง

### การจัดการระบบผ่านหน้าเว็บ (สำหรับ Admin)

| การจัดการ | วิธีทำ |
| --- | --- |
| เพิ่มบัญชีเจ้าหน้าที่ | ไปที่หน้า Admin -> บัญชีเจ้าหน้าที่ -> กรอกอีเมล ชื่อ และเลือกหน้าที่ ระบบจะส่งลิงก์สำหรับตั้งรหัสผ่านไปให้ทางอีเมล (ลิงก์ใช้ได้ครั้งเดียว และมีอายุ 24 ชั่วโมง) |
| กรณีเจ้าหน้าที่ไม่ได้รับอีเมลคำเชิญ | กดปุ่ม "ส่งคำเชิญอีกครั้ง" บนหน้าเว็บ หรือรันคำสั่งบนเซิร์ฟเวอร์ `docker compose exec backend python scripts/invitation_link.py --email <อีเมล>` เพื่อนำลิงก์ไปส่งให้เจ้าหน้าที่โดยตรง |
| ระงับ หรือ เปิดใช้งานบัญชีเจ้าหน้าที่ | ไปที่หน้า Admin -> บัญชีเจ้าหน้าที่ แล้วเปลี่ยนสถานะบัญชี |
| เปลี่ยนสายงาน/หน้าที่ของเจ้าหน้าที่ | ให้ลบบัญชีเดิมออกแล้วส่งคำเชิญใหม่ด้วยอีเมลเดิม (ประวัติการทำงานเดิมจะยังคงอยู่ในระบบ) |
| เพิ่มห้องและสร้าง QR Code | ไปที่หน้า Admin -> ห้อง/QR -> กดเพิ่มห้อง -> กด Generate QR แล้วดาวน์โหลดไฟล์ไปพิมพ์ติดหน้าห้อง |
| ปิดการแจ้งเรื่องของห้องชั่วคราว | กดปิดใช้งานห้องนั้น (ผู้ใช้จะสแกน QR ของห้องนั้นเพื่อแจ้งเรื่องใหม่ไม่ได้ แต่รายการแจ้งซ่อมเดิมยังดูได้ปกติ) |
| ลืมรหัสผ่าน | กด "ลืมรหัสผ่าน" ที่หน้าเข้าสู่ระบบ ระบบจะส่งลิงก์รีเซ็ตรหัสผ่านให้ทางอีเมล (ลิงก์มีอายุ 30 นาที) |

*หมายเหตุ:* หากกรอกรหัสผ่านผิดติดต่อกันครบ 5 ครั้งภายใน 15 นาที ระบบจะล็อกการเข้าสู่ระบบชั่วคราวเป็นเวลา 15 นาที

## ส่วนที่ 4: การแก้ปัญหาเบื้องต้น

หากระบบทำงานผิดปกติ แนะนำให้เช็ก Log ก่อนเสมอด้วยคำสั่ง `./deploy/bcare.sh logs backend`

| อาการที่พบ | สาเหตุและวิธีแก้ไข |
| --- | --- |
| รัน `install` ในขั้นตอนที่ 3-5 แล้วหยุดทำงาน พร้อมแจ้งรายการ `REPLACE_` | ยังกรอกค่าในไฟล์ `.env` ไม่ครบ ให้กลับไปทำขั้นตอนที่ 4 อีกครั้ง |
| ขึ้น `Permission denied` เวลาใช้คำสั่ง `docker` | ยังไม่ได้ออกจากระบบแล้วล็อกอินใหม่หลังจากทำขั้นตอนที่ 1 ให้พิมพ์ `exit` แล้วเชื่อมต่อเข้ามาใหม่ |
| ขึ้น `Permission denied` ตอนรัน `git clone` | ลืมรันคำสั่ง `sudo mkdir ...` ในบรรทัดแรกของขั้นตอนที่ 2 |
| ขึ้น `R2: FAILED` | - `AccessDenied`: API Key ไม่มีสิทธิ์เขียนไฟล์<br>- `NoSuchBucket`: พิมพ์ชื่อ Bucket ผิด<br>- `SSLError`: กรอก Account ID ผิด หรือเซิร์ฟเวอร์ออกอินเทอร์เน็ตไม่ได้ |
| ขึ้น `SMTP: FAILED` | กรอก Username หรือ App Password ผิด หรือพอร์ต 587 ถูกบล็อก (ระหว่างรอแก้ไข สามารถใช้สคริปต์ `invitation_link.py` ตามตารางในส่วนที่ 3 เพื่อสร้างลิงก์เชิญเจ้าหน้าที่ไปก่อนได้) |
| เข้าหน้าเว็บแล้วขึ้น `502` หรือ `504` | ระบบยังสตาร์ทไม่เสร็จหรือหยุดทำงาน ให้เช็กด้วย `./deploy/bcare.sh status` (หากใช้ Reverse Proxy ให้ตรวจว่าตั้งค่า `FRONTEND_BIND_ADDRESS` ถูกต้องแล้ว) |
| ใช้ Reverse Proxy (รูปแบบที่ 2) แล้วเข้าเว็บขึ้น `403 Forbidden` | ค่า `EDGE_PROXY_CIDR` ไม่ตรงกับ IP ที่เครื่อง Proxy วิ่งเข้ามา ให้รัน `./deploy/bcare.sh logs frontend` ดูเลข IP ต้นบรรทัดของรายการที่ลงท้ายด้วย `403` แล้วนำ IP นั้นไปใส่ใน `EDGE_PROXY_CIDR` ในไฟล์ `.env` จากนั้นรัน `./deploy/bcare.sh install` (แต่ถ้า IP ขึ้นต้นด้วย `172.` แสดงว่าตัว Proxy รันอยู่บนเครื่องเซิร์ฟเวอร์เดียวกัน **ห้ามใส่ IP นั้น** ให้สลับไปตั้งค่าตามรูปแบบที่ 1 แทน) |
| รัน `install` แล้วหยุดพร้อมแจ้งเตือนเรื่อง `EDGE_PROXY_CIDR` | มีการเปลี่ยนค่า `FRONTEND_BIND_ADDRESS` แต่ยังไม่ได้ระบุ IP ของเครื่อง Proxy ให้กลับไปกรอกตารางส่วนท้ายของขั้นตอนที่ 4 |
| อัปโหลดรูปภาพไม่ผ่าน ขึ้นรหัส `413` | เครื่อง Proxy หรือ Nginx จำกัดขนาดไฟล์ไว้ต่ำเกินไป ต้องตั้งค่า `client_max_body_size 60m` เพิ่มเติม |
| ขึ้น `Pool overlaps` หรือ `port is already allocated` | พอร์ตหรือวงจรเครือข่ายของ Docker ชนกับโปรแกรมอื่นในเครื่อง ให้เปลี่ยนค่า `APP_SUBNET` หรือ `FRONTEND_PORT` ในไฟล์ `.env` |
| สร้างบัญชี Admin ตอนติดตั้งไม่ผ่าน ขึ้น `Invalid ...` | รหัสผ่านที่ตั้งไม่ตรงตามเงื่อนไข หรือรูปแบบโดเมนอีเมลไม่ถูกต้อง |
| ล็อกอินแล้วขึ้นรหัส `429` | กรอกรหัสผ่านผิดเกินจำนวนครั้งที่กำหนด ให้รอ 15 นาทีแล้วลองใหม่ |

## ส่วนที่ 5: สำหรับนักพัฒนา (Developers)

การรันระบบเพื่อพัฒนาและทดสอบบนเครื่องตัวเอง:

```bash
# รันระบบทดสอบที่ http://localhost:5173 (บัญชีทดสอบ: admin@example.com / Admin@1234)
# *ห้ามใช้คำสั่งนี้รันบนเซิร์ฟเวอร์ใช้งานจริง*
docker compose up --build

# รันชุดทดสอบ Automated Tests
cd Backend && uv run --extra dev pytest
```

- ดูรายการตัวแปรตั้งค่าทั้งหมดพร้อมคำอธิบายละเอียดได้ที่ไฟล์ [`.env.production.example`](.env.production.example)
- สำหรับการติดตั้งแบบอัตโนมัติโดยไม่ต้องพิมพ์โต้ตอบหน้าจอ (Non-interactive install) ดูวิธีทำได้ที่ [INITIAL_ADMIN.md](Backend/scripts/INITIAL_ADMIN.md)
